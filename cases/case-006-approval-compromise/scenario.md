# Scenario and ground truth

An object-deletion request is presented as a harmless test preview. A scripted reviewer approves previews and denies production deletion. The control presents the actual target and consequence from the request rather than the manipulated display. The approval evidence retains what was displayed and the available rejection path.

## Experiment design

The executable scenario is `scripts/simulations.py`, case 6. Both conditions
run deterministic Python state transitions. The changed control is:

Bind the review display to the exact target and consequence of the requested action.

Raw source payloads, state snapshots, normalized records and probe results are
generated by execution. The case tests the modeled relationship, not prevalence,
model accuracy, real-world exploitation success, or production containment.

## Trust boundaries and required logs

Tool request, exact review display, approval-store decision and downstream object state.

In a real deployment, collect each source under its owning system's authority,
preserve request IDs and content hashes, and export evidence outside agent control.
Here every source is simulated by the same process. This is a scripted reviewer, not a human-subject experiment. Review time, competence, coercion and real human judgment are unmeasured.

## Ground-truth boundary

The before/after snapshots describe only the named simulation inventory. A missing
resource or consumer is not proven absent outside that inventory. Failure and
control traces are separate experiments; the control does not erase the failure.
