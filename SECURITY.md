# Security policy

## Reporting a security issue

Do not open a public issue for a vulnerability that could expose real systems, credentials, personal information, proprietary prompts, provider bypasses, or active exploitation methods.

Until a dedicated disclosure address is published, contact the maintainer through a verified professional channel and label the message **AI Forensic Readiness security report**. Do not include secrets in the initial message.

## Repository safety rules

- Reference cases must use synthetic identities, data, credentials, and endpoints.
- Evidence bundles must be reviewed for secrets and personal information before publication.
- Examples must not contain live tokens, internal hostnames, customer identifiers, or recoverable confidential content.
- Attack cases should demonstrate investigation requirements without publishing unnecessary weaponization detail.

## Supported versions

Only the latest tagged discussion draft receives corrections. No version should be treated as production security guidance without local validation.
