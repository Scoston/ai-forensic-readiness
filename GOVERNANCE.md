# Governance

## Current model

During the discussion-draft stage, Dr. Stephen Coston serves as the project maintainer and release editor. Decisions should be documented in issues, pull requests, or RFCs rather than private conversations whenever disclosure is appropriate.

## Decision principles

1. Evidence over preference.
2. Investigation utility over field accumulation.
3. Existing interoperability over unnecessary invention.
4. Proportionate collection over indiscriminate prompt retention.
5. Explicit uncertainty over false completeness.
6. Reproducible cases over unsupported maturity claims.

## Decision process

- Minor editorial changes may be merged after maintainer review.
- Material semantic changes require a public proposal and documented disposition.
- Breaking schema changes require an RFC and a versioning decision.
- A proposal may be accepted, accepted with modification, deferred pending evidence, or rejected with rationale.

## Future steering group

A multi-stakeholder steering group should be considered only after sustained external use and contribution. It should include incident response, AI engineering, IAM, privacy, governance, cloud security, and evidence/forensics perspectives. Participation should be based on demonstrated work, not sponsorship.
